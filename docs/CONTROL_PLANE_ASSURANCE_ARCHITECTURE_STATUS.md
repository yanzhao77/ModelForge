# 控制面保证架构状态与后续路线图

## 1. 状态口径

本文档描述 ModelForge 在 CP1–CP4 后的**静态架构状态**。其中，CP1–CP3 已包含在本地提交 `fcc08b74930531156317061c38bcbedbe5c8fa45`，但最近一次 GitHub 只读核对显示远端 `master` 仍在 `7d8fdc1d2adfbb55458b2032ca4d7ebc327b60d5`，因为两次正常 HTTPS 推送均超时。CP4 代码及本文件仍在本地工作区，尚未提交。

> 这不是行为验证、并发验证、兼容性验证或发行批准。所有实际控制面、GUI、SSE、迁移、模型/provider、Agent、任务、训练、插件/MCP、构建、签名与发布均保持未运行状态。

## 2. 整体分层架构

| 层级 | 主要构件 | 已建立职责 | 运行性边界 |
|---|---|---|---|
| 策略与契约层 | `action_risk.py`、`control_plane_contracts.py`、`control_plane_errors.py` | 为高风险动作定义风险级别、确认要求、对象类型、允许审计字段、稳定错误和预览资格。 | 仅提供不可变查询；不访问数据库或执行动作。 |
| 所有权层 | `resource_access.py`、`security.py` | 定义当前用户/管理员作用域、统一不可用与版本冲突语义；管理员拒绝携带稳定关联标识。 | 路由必须先进行用户范围查询；辅助代码不查对象。 |
| 协调层 | `audit_log.py`、`control_plane_coordination.py` | 区分同会话持久化、提交后调度、独立运行性副作用和只读动作；约束 `persisted`、`accepted`、`durability_unknown`、`read_only` 回执。 | 不把审计未知或接受状态表述为执行成功、回滚或安全重放。 |
| API 控制面层 | Agent、Task、Training、Workspace、Memory、Plugin/MCP 路由 | 对已迁移动作执行显式确认、关联标识、用户范围、版本摘要和脱敏审计。 | 运行性服务仍独立于 API 审计边界；不能推断跨资源原子性。 |
| 意图预览层 | `execution_intent_preview.py`、Workspace 预览端点 | 生成用户绑定、短期、内容无关的动作/目标/版本摘要；检查结果恒定阻断执行。 | 不查目标、不持久化、不写审计、不执行动作；预览令牌不是执行令牌。 |
| 桌面客户端层 | REST 客户端、`AsyncApiMixin`、安全错误格式化、本地化、预览视图模型 | 仅在已有用户确认后传递确认参数；显示稳定错误码与关联标识；协作取消替代强制终止。 | 不自动确认、不显示 token/摘要/原始异常，也不由预览视图授予执行能力。 |
| 治理与证据层 | EI 映射、错误目录、所有权/协调/预览设计文档 | 固化验证最小证据、固定 SHA、脱敏、No-Go 和发行阻断。 | 文档不能替代测试、审计、签名、验收或 Release。 |

CP4 的实现和相关待办/路线图处于本地未提交状态，不能视为候选版本。CP1–CP3 虽已有本地提交，但在网络恢复并完成正常 Git 推送前，GitHub `master` 不包含该提交。不可变标签 `v0.1.3-dev` 的既有提交目标不得移动、重写或删除。

## 5. CP5–CP8 顺序路线图

| 顺序 | 工作包 | 目标 | 允许的静态交付 | 明确禁止 | 完成门槛 |
|---:|---|---|---|---|---|
| CP5 | 桌面控制面覆盖矩阵 | 消除页面对确认、请求键、关闭回收、本地化与安全错误展示的遗漏。 | 页面—API—风险动作—i18n—异步生命周期矩阵；纯视图/调用点收敛。 | 启动 GUI、SSE、API 请求或模拟点击。 | 静态扫描无原始异常展示、无强制终止和无自动确认路径。 |
| CP6 | 验证证据登记册 | 将控制面契约、候选 SHA、最小化证据与 No-Go 逐项关联。 | 空白证据登记结构、取证字段白名单、验证前检查表。 | 固定候选 SHA、截图、网络/数据库取证或通过结论。 | 证据字段不含正文、凭据、路径或原始异常。 |
| CP7 | 并发与迁移设计冻结 | 为 Run、事件、计划和 outbox 定义持久状态版本、lease、唯一键、CAS 与迁移前置条件。 | 数据模型/迁移设计、兼容窗口和回滚策略文档。 | DDL、迁移、恢复、数据修复或并发压力验证。 | 设计说明租约过期、冲突、重复事件和迁移失败的 No-Go。 |
| CP8 | 发行治理复核 | 整理版本、签名、跨平台安装与审批要求。 | 发行检查表、审批责任、候选 SHA/证据引用结构。 | 修改版本、创建 tag、构建、签名、上传产物或发布 Release。 | 正式发行继续被固定 SHA、完整验证、签名、安装证据及人工批准共同阻断。 |

## 6. 验证隔离与发行 No-Go

任何未来行为验证都必须依序满足：工作区干净且已提交；唯一完整 40 位候选 SHA 固定；获得明确授权；使用隔离用户和最小化脱敏数据；按错误目录和证据映射记录关联标识。以下任一情形均为 No-Go：未确认动作发生、对象可被跨用户枚举、正文/凭据/路径进入响应或日志、重复副作用、审计未知被描述为成功、原始异常或混合语言进入桌面 UI、候选 SHA 漂移，或未经授权执行运行性操作。

## 7. 推荐下一步

下一静态工作包应为 **CP5 桌面控制面覆盖矩阵**。它不改变高风险动作的服务端语义，却能将 CP1–CP4 契约落实到页面级审阅清单，并为后续固定 SHA 验证准备可追溯的桌面证据范围。网络恢复后，应先正常推送本地 `fcc08b7` 提交，再单独审阅并归档 CP4；任何推送都不得附带标签或 Release 操作。
