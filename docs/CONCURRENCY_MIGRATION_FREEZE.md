# CP7 并发与迁移设计冻结

**状态：** 静态设计冻结，未执行 DDL、迁移、回填、恢复或并发验证。  
**目标：** 将 Run、事件、计划 occurrence、任务 outbox 和指标派送的持久化事实、未来追加迁移和运行性验证边界分离，避免以进程内状态或文档结论替代数据库事实。

## 1. 当前 ORM 静态事实

当前 ORM 已声明多项 C3 所需持久字段和唯一索引，但其实际 SQLite 架构、旧库兼容、CAS 竞态、lease 恢复和发布行为均未运行验证。因此，“当前存在”仅表示代码模型声明，不表示数据库已经升级或运行性契约已满足。

| 领域 | 当前声明字段/索引 | 当前结论 | 不允许的推断 |
|---|---|---|---|
| Agent Run | `state_version`、`executor_lease_id`、`lease_expires_at`、`terminal_event_key`；`terminal_event_key` 唯一索引。 | 模型支持 CAS/lease 设计。 | 不得推断运行时使用 CAS、lease 已恢复或终态唯一已验证。 |
| Agent Event | `event_key`；`(run_id, event_key)` 唯一索引。 | 模型支持事件幂等键。 | 不得推断历史事件已回填、重放无重复或 SSE 已验证。 |
| 计划执行 | `occurrence_key`、claim 字段、版本/尝试计数；`(schedule_id, occurrence_key)` 唯一索引。 | 模型支持 occurrence claim。 | 不得推断计划回调、手动运行或恢复流程无重复。 |
| 任务 Outbox | `event_id` 唯一、租约、尝试和下一次尝试字段。 | 模型支持事件级去重和派送租约设计。 | 不得推断真正的至少一次/恰好一次派送。 |
| 指标派送 | `emission_key` 唯一。 | 模型支持终态指标独立去重。 | 不得将指标派送成功作为 Run 成功条件。 |
| 任务请求幂等 | `idempotency_key` 已存在，但非空值尚无 `(user_id, idempotency_key)` 唯一约束。 | 需要未来追加迁移。 | 不得用标题、正文或 metadata 内容替代幂等键。 |

## 2. 冻结的不变量

| 不变量 | 持久化事实来源 | 验证前禁止事项 |
|---|---|---|
| Run 单一终态 | 带预期 `state_version` 的条件更新，终态 event key。 | 不依赖 `_running` 等内存集合裁决终态。 |
| occurrence 单一 claim | `(schedule_id, occurrence_key)` 唯一约束与带 lease 的状态记录。 | 不先创建 Run 再查找活动计划。 |
| 事件可重放去重 | `(run_id, event_key)` 与持久 cursor。 | 不只用递增 sequence 假定重试安全。 |
| outbox 失败可观察 | 独立 event/outbox 记录、有限尝试和脱敏错误码。 | 不静默忽略派送失败或阻塞主状态。 |
| 请求幂等 | 用户范围内、内容无关的显式 idempotency key。 | 不以输入、标题、路径、异常文本或模型输出去重。 |

## 3. 未来迁移的仅追加序列

迁移只能在独立授权下进行，并须遵循现有迁移预检、备份与发布门槛。以下顺序是冻结设计，而非可立即执行的操作。

| 顺序 | 未来迁移步骤 | 兼容窗口 | 禁止变更 |
|---:|---|---|---|
| 1 | 在隔离副本运行只读 schema 预检，确认字段/索引真实状态。 | 不写入生产库。 | 不自行创建、删除或重建表/索引。 |
| 2 | 只追加缺失字段与唯一约束；对历史数据保留 nullable 兼容。 | 旧代码可读、但不使用新 CAS/lease。 | 不删除/重命名旧字段，不按正文回填。 |
| 3 | 部署双读/单写兼容逻辑，仅对新动作写新 key/version/lease。 | 观察期内保留旧行兼容读取。 | 不启用自动恢复或自动重试。 |
| 4 | 在固定 SHA 和隔离环境验证 CAS、重复 occurrence、迟到回调、outbox lease 与 emission 去重。 | 仅授权最小对象/计数。 | 不连接真实 provider、训练或发布流程。 |
| 5 | 经人工 Go/No-Go 审核后才考虑收紧非空约束或启用恢复。 | 需要可回滚的应用部署策略。 | 不用破坏性 DDL 代替回滚。 |

## 4. 回滚与恢复边界

数据库回滚不得通过删除刚添加的字段、唯一索引或历史记录完成。发生异常时，应暂停新写入路径、保留脱敏诊断与最小计数、切回兼容读路径，并由授权维护者决定应用版本回退或隔离副本修复。lease 过期只代表需要后续设计的恢复资格，不等价于可以自动重跑 Agent、任务、训练、插件或 MCP 动作。

## 5. 实施/验证 No-Go

在出现以下任一情况时，不得执行后续迁移或将结果表述为完成：缺少完整候选 SHA；数据库未备份或预检未授权；发现正文、凭据、路径或原始异常进入迁移/证据；同一 occurrence 或终态没有唯一约束；CAS 失败路径可能覆盖更新状态；派送/指标失败影响主结果；或任何恢复策略可能未经用户确认重启高风险动作。

## 6. 静态代码目录

`backend/app/core/concurrency_migration_contract.py` 是 CP7 的无副作用结构清单。它只描述当前 ORM 声明和未来迁移条件，不导入 SQLAlchemy、数据库连接、迁移框架、运行时或调度器，也不包含 DDL、回填、恢复或任务执行调用。

## 7. 后续验证入口

只有固定候选 SHA、明确授权、隔离数据库/用户和脱敏证据范围齐备后，才可向 `CONTROL_PLANE_VERIFICATION_LEDGER.md` 填写 CP7 行。验证应从 schema 预检和零副作用冲突分支开始，任何 No-Go 均终止后续验证、迁移、构建、签名和发行步骤。
