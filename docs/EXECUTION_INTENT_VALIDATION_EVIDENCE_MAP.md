## 3. 统一 No-Go 门槛

验证、归档和任何候选发行均必须停止，且不得将结果表述为通过，只要发现下列任一情况。

| 编号 | No-Go 条件 | 必需处置 |
|---|---|---|
| NG-EI-01 | 未提交 `confirm=true` 仍创建、执行、取消、批准、拒绝、重试、停止、训练或注册对象。 | 停止验证，隔离环境，记录稳定事件摘要并修复确认守卫。 |
| NG-EI-02 | 控制面响应、审计、事件、日志、截图或文档含输入正文、metadata 正文、提示词、工具参数、模型输出、路径正文、数据集正文或任何凭据。 | 停止保存/共享证据，清理受影响的证据介质并修复脱敏边界。 |
| NG-EI-03 | 跨用户可读取或改变目标，或错误响应泄露其他用户目标是否存在。 | 停止验证，修复用户作用域与无枚举泄露响应。 |
| NG-EI-04 | 同一确认重试产生重复 Run、重复任务或重复副作用，且没有稳定冲突/幂等说明。 | 停止验证，补充幂等与版本契约。 |
| NG-EI-05 | 服务内部提交与审计持久化未能协调，却返回“已执行”或“成功”。 | 停止验证，采用明确的 `pending`、`accepted` 或稳定失败回执。 |
| NG-EI-06 | 三语言动态提示混用静态语言，或呈现 HTTP/异常正文而非稳定错误码与关联标识。 | 停止桌面验收，修复本地化和错误展示边界。 |
| NG-EI-07 | 验证触发未经授权的真实 provider、模型推理、SSE 持续消费、训练进程、构建、签名、标签或 Release。 | 立即停止相关动作，保留最小化计数摘要并重新取得授权。 |
| NG-EI-08 | 候选 SHA 不是单一、完整的 40 位值，或证据混用了不同提交。 | 证据无效；固定候选提交后从头收集。 |

## 4. 固定 SHA 后的证据收集顺序

获得授权时，必须按如下顺序执行并在每一步出现 No-Go 时停止。每个步骤只采集所列的最小化数据；不得为“覆盖率”补充额外的真实运行或外部调用。

| 顺序 | 阶段 | 允许的结果 | 禁止的结果 |
|---:|---|---|---|
| 1 | 固定候选提交与范围审阅 | 40 位 SHA、变更清单、授权记录。 | 移动开发标签、创建正式标签或 Release。 |
| 2 | 未确认拒绝与关闭/取消确认检查 | 稳定拒绝码、零副作用计数摘要。 | 模型调用、训练、provider 验证或批量重试。 |
| 3 | 授权的最小单对象确认检查 | 一个隔离对象的接受/状态/审计头字段摘要。 | 用户输入正文、模型输出、数据集/路径正文。 |
| 4 | 用户范围、重复确认与版本冲突检查 | 隔离响应类别与幂等/冲突摘要。 | 跨用户对象详情或未经授权对象探测。 |
| 5 | 三语言桌面检查与脱敏证据审阅 | 三张最小化截图和静态文本检查结果。 | GUI 之外的真实 provider、训练或发布动作。 |
| 6 | 独立 Go/No-Go 评审 | 完整性、脱敏、授权与跨平台门槛结论。 | 正式 tag、签名、资产上传或 GitHub Release。 |
