# ModelForge v0.1.3-dev 非测试型续开发设计文档

> **注意：** 历史设计文档，基于 v0.1.3-dev 阶段编写。不代表 v0.1.3-beta.1 发行状态。

**作者：** Manus AI
**适用基线：** `aed94979357678673d9f426be101a20837248c68` 及其后续本地开发提交。
**目标：** 在不执行测试、服务启动、真实迁移、模型调用、计划运行、插件动作、构建、签名、发布或推送的约束下，完成剩余可开发工程的设计与实现准备。

## 1. 范围与工作原则

v0.1.3-dev 已具备 I1 迁移预检、I2 运行时诊断、I3 插件控制面契约、I4 生命周期快照、I5 部分桌面请求编排与 I6 发行决策材料的基础实现。[1] 本文覆盖这些基础能力之后仍可继续完成的**非执行性**工作：其重点是把状态、契约、审计、界面和文档收敛为可审阅的工程对象，而不是调用真实系统去证明它们正确。

> **边界声明：** 本文中的“完成”只表示代码或文档设计已写入。数据库升级、旧库副本恢复、并发竞争、SSE 重放、插件补偿、桌面交互、签名和安装验证必须留到后续取得明确授权的验证阶段。[2] [3]

| 原则 | 设计要求 | 禁止行为 |
|---|---|---|
| 显式意图 | 每个会改变状态的端点都必须有确认字段、关联标识和审计记录。 | 页面加载、诊断读取或轮询不得触发 Run、计划、插件或恢复动作。 |
| 最小披露 | 诊断与审计仅保存状态、计数、稳定标识、时间和脱敏摘要。 | 不保存密钥、令牌、正文、完整 prompt、产物内容或未脱敏异常载荷。 |
| 不可变追溯 | 开发快照、发行候选和证据清单均固定到完整提交 SHA。 | 不重写已共享的开发标签或用浮动分支替代候选身份。 |
| 验证隔离 | 开发实现与实际验证分为不同任务并由用户分别批准。 | 不把静态检查或历史 CI 当作当前候选的验证证据。 |

## 2. NT1：控制面契约与审计扩面

### 2.1 目标

插件控制面已采用 `confirm`、`correlation_id` 和脱敏操作审计；下一步将这一模式扩展到 Agent 定义、模型配置、知识集合与自动化恢复控制面。目标是让所有写入端点在不改变旧客户端可读字段的前提下，具备稳定输入、稳定失败类型和可查询的最小审计关联。

| 契约对象 | 建议字段 | 成功响应 | 失败响应 | 审计摘要 |
|---|---|---|---|---|
| 受确认动作请求 | `confirm`、可选 `request_id`、可选目标版本。 | `ok`、`correlation_id`、兼容历史字段。 | `code`、`message`、`correlation_id`。 | 动作名、对象类型/ID、操作者、结果、关联标识。 |
| 普通配置写入 | Pydantic 字段、可选 `expected_version`。 | 版本、更新时间、关联标识。 | `VALIDATION_ERROR`、`CONFLICT`、`FORBIDDEN` 等稳定 code。 | 字段名列表与脱敏键，不保存原始值。 |
| 只读审计查询 | 时间窗、动作类型、对象类型、分页 cursor。 | 无内容条目列表与下一页 cursor。 | `FORBIDDEN`、`INVALID_CURSOR`。 | 无新增审计记录。 |

### 2.2 实施顺序

首先为 Agent 定义、模板和自动化恢复接口补齐 Pydantic 请求模型；其次将模型/知识配置写入统一到 `problem` 错误与 `correlation_id`；最后新增管理员只读审计列表和 retention 策略配置的**预览**。历史自由 JSON 请求保留兼容适配层，不在本周期删除旧字段。每一端点必须在服务层验证用户归属，再写入审计服务。

### 2.3 非目标

本工作包不启动插件、不恢复计划、不创建 Run、不调用模型，也不在没有验证证据时启用审计自动清理。

## 3. NT2：生命周期、补偿与 retention 的受控治理

### 3.1 状态模型

当前 I4 提供 Runtime/Scheduler 的只读快照。后续治理应在此基础上引入“预览 → 明确确认 → 幂等执行 → 审计可追溯”的单向控制模型。操作请求必须包含 `operation_id` 或客户端 `request_id`；服务端将其映射到持久审计记录，重复请求返回既有结果而不重复执行。

| 治理对象 | 只读预览 | 未来受确认动作 | 补偿或阻断 |
|---|---|---|---|
| 计划恢复 | 暂停原因、失败次数、下一次触发、运行中 claim。 | 仅恢复指定已暂停计划。 | 存在有效 claim、已运行或权限不足时阻断。 |
| retention 候选 | 候选数量、最早/最新时间、规则版本、受影响对象类型。 | 仅按预览 token 清理候选。 | token 过期、候选变化或证据不足时拒绝。 |
| 插件补偿 | scope、挂载状态、generation、依赖阻塞。 | 仅卸载明确指定且无反向依赖的 scope。 | 加载失败回滚；保留操作尾迹。 |
| Runtime 关闭恢复 | 残留任务数、取消请求数、等待阶段。 | 仅管理员触发有界关闭或诊断清理。 | 不强制终止线程；超时后记录人工干预项。 |

### 3.2 预览令牌设计

对于会删除或恢复状态的动作，预览响应生成一个短期、用户绑定且对象集合哈希固定的 token。确认动作必须同时提交 `confirm=true`、token 与对象版本；服务端若发现对象集合、版本或用户不匹配则返回 `PREVIEW_STALE`。token 本身不携带密钥或对象正文，只存储不可逆摘要和过期时间。

## 4. NT3：桌面请求编排与三语言收敛

I5 已在控制中心与自动化页面引入请求代次和关闭回收。后续范围应覆盖 Agent 工作台、扩展治理、模型页、知识页和任务详情页，形成每页统一的 `AsyncApiMixin` 使用规范。

| 场景 | 规范 | 用户可见结果 |
|---|---|---|
| 同页连续刷新 | 同一 `request_key` 的旧代次结果必须丢弃。 | 新选择的对象不会被旧请求覆盖。 |
| 关闭页面 | 请求标记为取消、连接信号断开、线程在完成时回收。 | 关闭不强制终止线程，不弹出过期错误。 |
| 网络超时 | 显示可本地化的超时说明和可复制的 `correlation_id`。 | 用户可重试读取，不会重复发送写操作。 |
| 高风险写操作 | 对话框使用统一 `confirm` 文案、对象名和影响摘要。 | 取消不发起网络请求。 |
| 语言切换 | 标签、空状态、按钮、确认、错误和诊断说明都由资源键提供。 | zh-CN、en-US、ja-JP 不混用页面静态文本。 |

建议新增“文本键覆盖清单”，将每页可见静态文本与对应语言资源键列入文档。该清单是审计工具，不自动执行 UI 扫描或修改翻译。

## 5. NT4：不可变开发快照与文档治理

开发标签必须表达**历史快照**而非“当前最新开发”。现有 `v0.1.3-dev` 已固定在 B2–H7 提交，因此后续 I1–I6 基线应创建新的递增标签，例如 `v0.1.3-dev.1`，并在标签说明中写入完整 SHA、包含工作包和未验证声明。

| 文档或标签 | 非测试型治理动作 | 禁止动作 |
|---|---|---|
| 开发标签 | 新建注释标签、记录 SHA、工作包、创建时间与未验证状态。 | 移动、删除或强推已有共享标签。 |
| `todo.md` | 将历史已完成条目移入“历史记录”，保留当前有效未完成项。 | 删除发行、验证或安全决策历史。 |
| 开发计划 | 更新基线 SHA、实施状态和阻断项。 | 将未验证实现写为“已通过”。 |
| 发行材料 | 维护 SBOM/manifest/签名环境变量文档和 Go/No-Go 模板。 | 创建资产、访问证书或调用签名工具。 |

## 6. NT5：发行工程的非执行性准备

发行工程继续以“决策材料先于发行操作”为原则。可继续完成候选变更日志模板、证据 manifest JSON schema、签名预检的错误码说明、平台职责矩阵以及版本提升清单。正式版本号变更、标签创建、签名、资产打包、安装和发布均排除在本工作包之外。

| 交付物 | 内容 | 当前允许状态 |
|---|---|---|
| 候选 changelog 模板 | 固定 SHA、用户可见变更、兼容性说明、已知限制。 | 可编写，不可发布。 |
| 证据 manifest schema | gate 名称、passed 状态、脱敏证据引用、审批字段。 | 可定义，不可填充虚构证据。 |
| 平台职责矩阵 | Windows/Linux 签名、安装、审批、归档负责人。 | 可维护，不可读取 Secret。 |
| 版本提升清单 | `APP_VERSION`、manifest、SBOM、Release Notes、标签顺序。 | 可审阅，不可把开发版改为正式版。 |

## 7. 推荐实施顺序与完成定义

推荐按 `NT1 → NT2 → NT3 → NT4 → NT5` 顺序推进。NT1 先统一控制面写语义，NT2 在此基础上加入受确认治理，NT3 将语义可靠呈现在桌面端，NT4 记录不可变开发状态，NT5 最后形成发行决策材料。

“非测试型完成”要求所有新增状态写路径具备用户归属、确认/幂等边界、稳定错误码、关联审计与三语言资源设计；所有高风险动作具有预览或阻断条件；文档准确区分已实现、待验证和不可自动执行的事项。它不等于 API、数据库、桌面或跨平台发行已验证通过。

## 8. 暂缓项

下列任务在当前约束下暂缓：真实 SQLite 升级演练、Run/取消竞争、SSE/outbox 重放、计划恢复、插件加载/回滚、真实远程模型调用、CPU/GPU smoke、PySide6 离屏、构建、签名、原生安装、正式标签和 GitHub Release。它们必须使用固定候选 SHA、脱敏证据、受保护凭据和用户明确批准执行。[2] [3]
