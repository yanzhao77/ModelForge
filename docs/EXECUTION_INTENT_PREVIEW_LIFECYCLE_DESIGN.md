# CP4 执行意图预览生命周期设计

## 当前静态基线

现有 `execution_intent_preview` 使用短期签名令牌表达未来高风险动作的非持久化摘要。令牌带有 purpose、当前用户、动作、目标摘要哈希、预期版本摘要哈希、目标数量与过期时间；有效期限被限制在 60 至 900 秒。创建和确认检查端点均依赖当前登录用户，且所有检查结果显式返回 `execution_blocked=true`。

当前实现不查找目标、不写审计、不调用运行时、任务、训练、provider、插件或 MCP。预览令牌不是授权令牌，确认检查即使返回 `confirmation_valid=true`，也只说明令牌的静态确认契约匹配，不能执行后续动作。

## CP4 实施目标

| 目标 | 静态实现要求 | 禁止事项 |
|---|---|---|
| 动作绑定 | 令牌 action 必须存在于集中风险目录且需要确认；将动作、风险等级与对象类型一并摘要化。 | 不根据预览自动调用动作。 |
| 目标—版本绑定 | 对单目标/批量目标使用稳定、顺序无关、按目标标识绑定的版本摘要；缺失版本必须是显式安全状态。 | 不在预览时查库确认目标存在或读取对象正文。 |
| 用户范围 | 令牌 `sub` 只匹配当前认证用户；范围不符统一返回稳定错误码。 | 不通过错误差异泄露其他用户目标是否存在。 |
| 有效期 | 保持受限短期 TTL，明确过期、非法 purpose、动作不符与确认缺失的稳定回执，并登记到控制面错误目录。 | 不延长、刷新或重签发原令牌作为执行授权。 |
| 关联标识 | 请求关联标识仅进入 API 回执与受限审计语义，不作为共享目标数据。 | 不将用户输入、目标名称、路径、URL、token、API key 或正文写入令牌/摘要。 |
| 消费语义 | 因预览阶段无副作用，可重复检查；任何未来执行阶段必须使用独立、明确批准的意图消费策略。 | 不把多次确认检查视为幂等执行。 |

## 建议实现顺序

CP4.1 首先升级为版本化的摘要结构：目标标识仅参与不可逆哈希，版本按目标绑定后再规范排序；同时在声明性目录中登记预览支持的高风险动作。CP4.2 收敛创建与检查端点的稳定错误码、目的字段和 TTL 边界。CP4.3 为桌面客户端提供只读摘要的本地化呈现模型，但不将“确认”按钮连接到执行 API。CP4.4 仅在固定候选 SHA、明确授权及隔离验证环境中验证过期、范围不符、动作不符、摘要不符和未确认分支。

> **持续 No-Go：** 预览契约不得变更为执行令牌。任何将预览令牌、关联标识或摘要哈希用于执行高风险动作的方案，必须先完成独立的设计审阅、风险批准、固定候选 SHA 与最小化脱敏行为验证。
