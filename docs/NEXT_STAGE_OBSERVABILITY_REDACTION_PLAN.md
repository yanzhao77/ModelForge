# 下一阶段：运行时可观测性与脱敏加固计划

**同步基线：** `0bf9323296576a3ecb41140ba37160daf5e89f4a` 已推送至 `origin/master`。
**状态：** 规划与静态实现阶段。本文不构成测试、运行、迁移、构建、签名、标签或 Release 授权。

## 1. 目标与边界

当前主线已经具备控制面审计、只读诊断、计划生命周期协调、用户范围对话状态及 EventBus 聚合计数。下一阶段应优先缩小“事件和后台错误可能携带敏感文本”与“运行时内部异常仅落日志、缺少可读计数”之间的差距。所有改动必须保持本地优先、桌面优先和默认拒绝副作用的原则。[1] [2]

> **核心不变量：** API Key、Bearer token、密码、cookie、私钥、证书、原始模型输入输出、知识正文和未经脱敏的工具参数不得写入事件持久化、诊断响应、审计、指标、导出、日志或桌面 UI。

| 顺序 | 工作包 | 交付物 | 不做什么 |
|---:|---|---|---|
| OR1 | 运行时事件统一脱敏 | 事件发布前的递归脱敏与长度限制；严格保留事件类型、Run ID、序号和非敏感状态。 | 不重放、删除或执行历史事件。 |
| OR2 | EventBus 与后台任务只读诊断 | 队列深度、订阅者数、writer 状态、写失败、溢出、后台任务失败/无活动事件循环计数。 | 不自动启动、关闭或恢复 EventBus/Runtime。 |
| OR3 | 桌面诊断摘要与三语言 | 控制中心以聚合事实展示新增诊断，并保持请求键与关闭回收。 | 不显示正文、错误堆栈或任何敏感内容。 |
| OR4 | OpenAI 兼容接口错误契约 | 关联标识、稳定 problem code、脱敏错误摘要与可预测响应形状。 | 不调用外部模型或改变 OpenAI 兼容协议。 |
| OR5 | 证据映射与待办治理 | 新工作包到固定 SHA 验证 gate 的脱敏映射。 | 不运行 pytest、Ruff、服务、迁移或构建。 |

## 2. OR1：运行时事件统一脱敏

运行时会在创建 Run、工具调用和终态发布事件。所有这些路径必须在 EventBus 接收前经过同一递归脱敏函数，避免某个调用者遗漏工具参数、用户输入或错误文本。脱敏规则复用 `services.redaction.redact_data()`，同时对事件 payload 做确定性的深度与长度限制。Run ID、事件类型、序号、状态、计数、耗时和稳定错误码可以保留；输入正文、工具参数正文、模型输出正文和知识正文应替换为受限摘要或 `[REDACTED]`。

兼容策略为保留字段名与非敏感结构，新增 `payload_redacted=true` 等只读元数据只在确有脱敏发生时使用。不得将原文与脱敏副本同时持久化，也不得在异常分支绕过该边界。

## 3. OR2：只读运行时诊断

EventBus 已维护持久化写失败与队列溢出计数，运行时也维护后台 Task 注册表。下一步应以无正文、无对象 payload 的聚合字段公开：队列深度/容量、活跃订阅者数、writer 是否存在、写失败/溢出次数、追踪后台任务数、最近后台任务失败计数以及无活动事件循环导致的 spawn 拒绝计数。诊断必须只读取内存计数和数据库聚合，不得 `flush()`、`start()`、`shutdown()`、`publish()`、`cancel()`、恢复计划或清理数据。

## 4. OR3：桌面只读呈现

控制中心只新增显式点击的诊断摘要，不将其放入自动刷新链路。显示内容仅限布尔值、计数、状态、稳定错误码和截断/脱敏标记；不显示工具入参、事件 payload、异常堆栈或原始文本。新增按钮、标题、空状态与提示必须补齐简体中文、英语和日语资源。

## 5. OR4：OpenAI 兼容错误契约

OpenAI 兼容适配层的错误响应应提供关联标识与稳定代码，同时避免把底层异常文本直接回显。保留现有成功字段和流式协议；异常时仅返回协议允许的简短安全摘要。此改造仅调整失败响应构造，不能在规划或静态审阅期间发起真实 provider 请求。

## 6. OR5：未来验证门槛

未来授权后需固定候选 SHA，并验证：敏感字段不会进入 EventBus 持久记录、SSE 恢复仍保留顺序、队列满载与 writer 失败计数正确、无运行循环时后台 spawn 可诊断、桌面三语言/关闭路径可用，以及 OpenAI 兼容错误响应保持协议兼容。任何一项未验证时，版本、签名、tag 与 Release 继续保持 **No-Go**。
