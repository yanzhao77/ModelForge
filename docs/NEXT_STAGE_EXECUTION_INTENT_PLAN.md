# 下一阶段：执行意图与高风险控制面加固计划

**规划基线：** `c1622cdde20384fd28b6b27df03342e08bba5a03`（AC5 归档提交，已与 GitHub `master` 同步）。
**当前状态：** 仅规划。本文不会创建或执行 Agent Run、重试/取消任务、启动/停止训练、调用模型、启动 SSE、启用计划、加载插件、迁移数据库、构建、签名、打标签或创建 Release。

## 1. 目标与不变量

本阶段将把“用户明确意图”落实到仍可改变运行时状态的 API 和桌面入口。现有 AC1–AC5 已收敛远程 provider 配置、稳定 problem 响应、SSE cursor 和桌面摘要，但 Agent Run 创建/取消/审批、任务重试/取消及训练生命周期端点仍存在由一次普通请求直接触发状态变更或运行的历史路径。

> **核心不变量：** 没有明确、可审计且与当前用户和目标对象绑定的确认，客户端或 API 不得创建 Agent Run、重试任务、取消任务、批准/拒绝人工审批、开始/停止训练、注册训练模型或调用远程 provider。系统内部工作者的持久化状态上报不得误用交互式确认契约。

## 2. 工作包与顺序

| 顺序 | 工作包 | 目标交付 | 明确排除 |
|---:|---|---|---|
| EI1 | Agent Run 意图契约 | `execute` 默认安全值、一次性确认字段、稳定 problem code、关联标识和脱敏审计摘要。 | 不创建/执行 Run，不改变运行时调度。 |
| EI2 | 任务重试与取消治理 | 单任务/批量重试、取消请求的确认范围、去重目标摘要、部分失败稳定响应。 | 不重试、不取消、不投递 outbox 或启动执行器。 |
| EI3 | 训练生命周期治理 | 训练开始、停止、模型注册的显式确认、用户归属和审计契约。 | 不读取数据集、不启动/停止训练、不注册模型。 |
| EI4 | 桌面确认与三语言 | Agent、任务、训练入口只在确认对话框接受后传递确认；显示稳定错误码和关联标识。 | 不打开运行性页面流程、不模拟用户操作或调用 API。 |
| EI5 | 验证与发行隔离 | 固定候选 SHA 的执行意图、跨用户、重复确认、撤销、桌面关闭和脱敏审计证据映射。 | 不执行测试、构建、签名、tag 或 Release。 |

## 3. EI1：Agent Run 意图契约

`POST /agent/runs` 应让 `execute` 采用安全默认值，并要求在请求确实要创建运行时工作时同时提交明确的 `confirm=true`。创建草稿或仅校验配置的请求必须不排队、不调用 runtime worker。取消、批准和拒绝端点也必须使用具有关联标识的 Pydantic 请求体，且返回兼容字段与 `correlation_id`。

审计应只保存动作码、用户 ID、Run/Agent 标识、执行意图和确认布尔值，不保存输入、metadata、system prompt、工具参数或模型输出。若底层运行时无法原子地同时提交状态和审计，应采用“先持久化用户意图和审计、再提交后协调”的明确状态回执，而不能虚报已经执行。

## 4. EI2：任务重试与取消治理

面向用户的单任务重试、批量重试和取消需按用户作用域构造去重后的目标摘要，并要求明确确认。批量接口需清楚区分“请求未确认”“目标不存在/不属于用户”“状态冲突”和“已接受的用户意图”，并在响应中保留原有兼容任务字段。

`transition` 类端点可能被内部执行器用于写入任务进度或终态，因此不能简单要求交互式 `confirm=true`。该类端点应在后续实现中保留系统内部调用契约，并通过调用身份、预期版本或独立内部路由与用户交互 API 分离；未经验证不得声称隔离已生效。

## 5. EI3：训练生命周期治理

训练开始、停止与模型注册需要分别绑定任务或配置标识、当前用户、`confirm=true` 与关联标识。开始训练的确认不得把数据集字段、超参数原文或本地路径写入审计；模型注册的确认不得将模型产物内容或路径公开给无权用户。失败响应应沿用稳定 problem 结构，并保留内容无关的状态/计数摘要。

## 6. EI4：桌面确认与可解释性

桌面只可在用户点击确认按钮后发送 `confirm=true`。取消或关闭对话框必须保证不产生网络写请求。新增状态、提示、错误码和关联标识必须通过 `ui_localizer.py` 提供简体中文、英语、日语资源；动态错误仅显示稳定 code、关联标识和无正文描述。

## 7. EI5：执行意图验证与 No-Go

所有未来验证必须绑定一个完整 40 位候选 SHA，并收集请求计数、审计头字段、状态版本、用户作用域、重复确认、取消确认、关闭回收及脱敏 UI 截图。以下任一情况均为 No-Go：无确认仍触发执行、跨用户可见/可变更目标、审计包含正文/凭据、重复请求创建重复运行、动态 UI 混合语言，或验证引入未经授权的真实 provider 调用。

本计划完成不改变正式发行门槛。正式 tag、签名、资产上传和 GitHub Release 仍依赖完整验证、跨平台安装/签名证据、受保护审批与用户或发行负责人的明确批准。

## 8. EI6：集中式动作风险目录

在 `api_contracts` 或同等后端边界新增小型、可审阅的动作风险目录。目录只能描述动作码、风险等级、是否需要确认、目标类型和允许的审计字段；不得包含模型输入、URL 凭据、工具参数或由目录直接触发任何动作。现有 Agent Run、任务、训练、插件、MCP 和 provider 验证端点应渐进式查询该目录，而不是各自硬编码不一致的确认逻辑。

## 9. EI7：审计写入边界与失效回执

为写操作统一“领域意图 → 脱敏审计 → 单次提交”的边界。无法在同一事务中协调的运行时动作只能在提交后执行，并返回 `pending`、`accepted` 或稳定失败码；不得把协调失败表述为执行成功。审计辅助工具应只接受固定白名单摘要，并对不允许的键返回受控错误，不得序列化任意 metadata 或错误正文。

## 10. EI8：高风险动作预览与确认摘要

复用短期、用户绑定、摘要化的预览令牌模式，为未来 Agent Run、任务批量动作和训练动作提供“对象数量、稳定 ID 摘要、版本/哈希、过期时间”的预览契约。预览/确认检查必须严格只读，不能写审计、启动执行器、恢复任务、调用 provider 或创建运行对象。实际执行继续由后续授权和验证门槛决定。

## 11. EI9：任务所有权与版本冲突契约

任务读取、重试、取消及批量操作应统一以当前用户范围查找，并对预期版本、状态冲突和不存在/无权访问使用稳定、无枚举泄露的响应。对批量操作，返回的结果只能包含用户可见目标的稳定 ID、状态和错误码；不得在错误中披露其他用户任务是否存在。内部进度上报与用户动作须保持不同调用路径和权限语义。

## 12. EI10：Memory 与 Workspace 控制面收敛

Memory、artifact、collection、plugin profile 等配置型资源应采用 Pydantic 请求、归属检查、`correlation_id`、稳定 problem code 和脱敏审计。删除与关联变更需要明确确认；只读列表/详情不能因为诊断而执行清理、同步或加载插件。包含正文、文档内容、文件内容或运行结果的路径不在本轮静态实施范围。

## 13. EI11：插件与 MCP 动作确认一致性

插件已具备部分确认和审计能力；后续需与集中风险目录对齐。MCP server 的新增、删除、启用或连接相关动作需区分“保存配置”与“实际加载/连接”，并要求后者明确确认。实现不得安装、加载、启动、停止、卸载插件，不得连接 MCP server，也不得将服务配置中的 token 回显。

## 14. EI12：运行预算与配额摘要契约

运行时、委托和工具策略只应公开预算上限、已使用/剩余计数、拒绝原因码和状态，不公开提示词、模型响应、工具参数或成本凭据。预算耗尽、委托深度和队列限制的控制面响应应可关联、可审计且无正文；不得为收集指标而发起 Agent Run、工具调用或模型推理。

## 15. EI13：统一控制面错误目录

将跨 API 的稳定错误码整理为受版本控制的目录，明确 HTTP 状态、用户可见安全消息、关联标识要求、是否可重试以及禁止暴露字段。目录是文档/辅助函数的单一事实来源，而不是自动重写现有全部端点的批量操作；每个迁移端点仍必须保留兼容字段。

## 16. EI14：桌面异步关闭与关联提示收敛

审阅未覆盖的训练、任务详情、Memory、Workspace、插件和 MCP 桌面入口，使后台请求具备请求键、协作取消和关闭回收。动态失败状态应从稳定 problem code 和 `correlation_id` 生成当前语言文本，不能显示原始异常。仅改变客户端并发处理，不触发页面动作或真实 API 请求。

## 17. EI15：文档治理与验证隔离

将 EI1–EI14 证据与先前 AC/OR/H7 矩阵对应，保留唯一固定候选 SHA、执行授权、未运行状态和 No-Go 门槛。历史 Git 网络故障、不可变开发标签、版本仍为开发版以及跨平台签名依赖必须保留可追溯性。未经完成验证、审批和用户发行授权，不得创建正式 tag 或 Release。
