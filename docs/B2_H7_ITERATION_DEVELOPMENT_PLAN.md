# ModelForge B2–H7 下一迭代技术开发计划

> **注意：** 历史开发计划，基于 v0.1.2-dev 阶段编写。不代表 v0.1.3-beta.1 发行状态。

**版本定位：** `v0.1.2-dev` 稳定性与并发治理迭代。
**作者：** Manus AI
**范围：** FastAPI、SQLAlchemy/SQLite、Agent Runtime、SSE、PySide6 与发行工程。
**状态：** 规划完成，尚未实施或验证。

## 1. 计划目的与编号约定

当前仓库不存在既有的 `B2–H7` 阶段编码。本计划将其定义为七个连续工作包：**B2** 数据基线、**C3** 并发状态机、**D4** 事件流、**E5** 计划与运行生命周期、**F6** 扩展治理、**G7** 桌面异步体验与 **H7** 验证/发行证据。这个顺序的核心原则是先收敛持久化和状态一致性，再改善观察、操作和发行，而不是继续叠加未受治理的执行入口。

> **总目标：** 在不改变“本地优先、显式执行、默认不运行”的产品边界下，让 Agent Run、计划、SSE、插件和桌面异步请求在取消、重试、重启、并发写入和页面关闭时具有可解释的状态、可追溯的审计和确定的资源释放路径。

| 约束 | 本周期承诺 | 明确不做 |
|---|---|---|
| 执行安全 | 浏览页面、保存草稿、刷新洞察、查看历史不创建 Run、不启用计划、不加载扩展。 | 自动执行 Agent、自动下载模型、自动训练。 |
| 隐私 | 指标、审计与错误只保存字段白名单和脱敏摘要。 | 持久化提示词、响应正文、API Key、Authorization、私钥或完整远程 URL。 |
| 自动化 | 保持本地受控计划；错过触发默认跳过。 | 未经产品决策提供应用关闭后的 24/7 执行。 |
| 发行 | 维护开发版本归档和证据模板。 | 将 `0.1.2-dev` 标记为正式 `v0.1.2`。 |

## 2. 技术债务与并发治理审计

审计确认，现有代码已经具备用户隔离、持久化事件、计划审计、运行取消和桌面后台请求的基础，但多个关键状态仍仅驻留在单进程内存中。SQLite 启动逻辑使用 `create_all()` 加显式增量列迁移，适合开发阶段但缺少版本化升级、回退与索引演进机制。[1] 计划、运行时和 SSE 则分别维护内存任务、集合、线程和队列；它们在多进程、进程重启、回调异常或慢客户端条件下缺少统一协调。[2] [3] [4]

| ID | 发现 | 风险 | B2–H7 处置 | 优先级 |
|---|---|---|---|---:|
| TD-01 | `create_all()` 与手写 `ALTER TABLE` 并行，迁移没有版本/回退账本。 | 升级差异、索引变更和历史库恢复不可证明。 | B2 建立版本化迁移基线与升级前检查。 | P0 |
| TD-02 | SQLite 未显式配置 WAL、busy timeout、写重试或写入队列策略。 | outbox、计划、运行和指标同时写入时出现锁竞争。 | B2/C3 制定单写入边界、短事务、重试退避与锁冲突指标。 | P0 |
| TD-03 | Scheduler 内存任务与持久化计划记录不是同一状态机，回调异常被吞掉。 | 重启、重复触发或失败后状态漂移。 | C3/E5 实现幂等 claim、终态 CAS 与可观察错误。 | P0 |
| TD-04 | Run 取消、执行和终态收尾依赖内存集合；事件订阅使用无界队列。 | 取消竞争、重复终态事件、慢 SSE 客户端内存增长。 | C3/D4 引入状态版本、有限队列、背压和断开策略。 | P0 |
| TD-05 | Outbox 发布线程仅进程内协作，至少一次唤醒没有 lease、指数退避或死信记录。 | 多进程重复投递、失败行永久重试、不可诊断积压。 | D4 增加 dispatcher lease、attempt 分类、退避和死信审阅。 | P1 |
| TD-06 | 插件生命周期使用全局内存状态与共享工具注册，装载失败没有显式补偿事务。 | 并发挂载/卸载、工具残留、跨 scope 污染。 | F6 增加生命周期锁、状态机、补偿与持久审计。 | P1 |
| TD-07 | `ApiWorker` 缺少协作取消和请求去重，关闭时可能强制终止线程。 | 页面关闭或重复刷新时 I/O 中断、旧响应覆盖新状态。 | G7 引入 request token、超时、取消协议和页面失效保护。 | P1 |
| TD-08 | 部分控制中心 API 直接接受 `dict[str, Any]`；错误码和审计字段未统一。 | 输入契约漂移、客户端错误处理不一致。 | B2/G7 迁移到 Pydantic 请求模型、统一 problem payload。 | P1 |
| TD-09 | 历史文档包含旧“全部测试通过/已完成”叙述，与当前未验证开发归档并存。 | 发行判断和维护结论被误导。 | H7 建立基线声明、证据索引和历史文档状态标签。 | P1 |
| TD-10 | 正式 Windows/Linux 签名、安装验证和审批门槛仍未满足。 | 开发快照被误标为正式发行。 | H7 维护不可绕过的 release gate，不创建正式标签。 | P0 |

## 3. 自动化与后台执行架构选项

本计划不把本地计划功能扩展成隐式云端服务。需要应用关闭后继续执行时，必须先由用户在下列路线中选择；在选择前，B2–H7 只治理现有本地受控模式。[5]

| 方案 | 运行体验 | 主要取舍 | 成本与复杂度 |
|---|---|---|---|
| A. 本地受控计划 | 应用/本地运行时启动时，仅恢复用户已启用计划；关闭应用即停止。 | 最符合本地优先与显式控制；无法提供 24/7 触发。 | 无新增托管成本，复杂度低。 |
| B. 常驻执行服务 | 用户可在应用关闭后保持计划运行，并由桌面端管理定义。 | 需要账户/凭据隔离、可用性、通知、队列、配额与运维治理。 | 需长期托管和运维，复杂度高。 |

本周期的实现顺序以 **A** 为基础假设；B 的架构决策、成本和托管方式不在未确认前落地。

## 4. B2–H7 工作包

### B2：数据基线、迁移与 API 契约

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| B2-01 | `core/database.py`、迁移目录、`records.py` | 引入版本化迁移账本；保留轻量迁移仅作为过渡读兼容。 | 新库、历史库升级路径可枚举；升级前检查拒绝未知/损坏 schema；不删除用户数据。 |
| B2-02 | Engine/session 配置、写入服务 | 明确 SQLite WAL、busy timeout、短事务、锁冲突重试与上限。 | 锁冲突有有限退避、可诊断错误码和计数；没有无限重试。 |
| B2-03 | `api/workspaces.py`、`agent.py`、`plugin.py` | 将自由字典请求迁移为 Pydantic schema，并统一 404/409/422/429 problem payload。 | 客户端可依据稳定 `code`、`message`、`correlation_id` 显示错误。 |
| B2-04 | redaction/audit 服务 | 统一审计字段白名单、UTC 时间、脱敏错误与操作关联 ID。 | 任何新增审计路径不能保存敏感正文或认证材料。 |

### C3：并发状态机与幂等控制

> C3 的具体实现决策已固化于 [C3 并发状态机与幂等控制技术方案](./C3_CONCURRENCY_AND_IDEMPOTENCY_DESIGN.md)。该方案选择数据库 CAS、持久 occurrence claim、事件幂等键和有限 SSE 背压；尚未进入 C3 代码实施或验证。

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| C3-01 | `runtime.py`、Run store | 为 Run 引入版本号或 compare-and-set 终态迁移。 | 取消、完成、失败任意并发顺序只产生一个持久终态和一个终态事件。 |
| C3-02 | `ScheduleService`、`ScheduledJob`、`ScheduleExecution` | 计划触发使用数据库 claim token、唯一触发键和事务化执行记录。 | 同一触发窗口在并发恢复/回调下最多创建一个 Run；`queue_one` 保留一个可解释待处理项。 |
| C3-03 | Runtime/metrics/outbox | 将 best-effort 失败记录改为有界、脱敏、关联 Run 的非阻塞诊断事件。 | 指标/flush 失败不改变主结果，但可按 correlation ID 查询。 |
| C3-04 | 取消/审批路径 | 取消传播与审批等待共享同一取消令牌和终态检查。 | 已取消 Run 不能被迟到审批恢复为运行中；子 Run 取消顺序可审计。 |

### D4：事件、SSE 与背压治理

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| D4-01 | `task_realtime.py`、TaskOutbox | Dispatcher 使用 lease/owner、有限 attempt、指数退避和死信状态。 | 多 dispatcher 不重复占有同一 outbox 行；达到上限的事件可审阅而非无限轮询。 |
| D4-02 | `stream_events`、任务流 API | 有界 SSE 队列、慢客户端策略、心跳和游标过期响应。 | 慢客户端不会导致无界内存；断线后可从持久 cursor 重放或收到明确 resync 指令。 |
| D4-03 | TaskStore/RunTimeline | 客户端持久 cursor 带 schema 版本、用户命名空间与去重窗口。 | 登录切换、事件保留清理、重复事件和 cursor 回退不污染其他用户视图。 |
| D4-04 | event/outbox 指标 | 记录 lag、队列深度、drop/resync、dispatch attempt，不记录事件正文。 | 控制中心可显示聚合健康摘要。 |

### E5：计划、运行与进程生命周期

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| E5-01 | `scheduler.py`、`ScheduleService` | 提取纯 next-run 计算与可注入 clock；删除静默 `except`。 | 每日/每周/间隔/一次性计划的恢复决策可重放；异常写审计并保持保守跳过。 |
| E5-02 | `main.py`、runtime shutdown | 明确启动顺序、恢复屏障、停止顺序与 deadline。 | 关闭时停止接收新触发、等待或标记在途工作、释放 dispatcher/SSE/调度资源。 |
| E5-03 | Schedule/Run API 与桌面页 | 提供只读“恢复决策说明”：上次恢复、错过策略、claim 状态、等待原因。 | 用户可区分草稿、暂停、排队、已跳过、失败暂停，且查看不执行。 |
| E5-04 | 审计/保留任务 | 为执行历史、outbox、指标桶定义本地 retention 和手动清理预览。 | 清理前显示范围/影响；不删除活动 Run、定义版本或未导出的产物。 |

### F6：插件与 MCP 生命周期治理

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| F6-01 | PluginManager、scope/registry | 以每扩展生命周期锁和状态机串行化 load/start/mount/unmount/unload。 | 并发请求不重复注册工具；非法状态转移返回 409。 |
| F6-02 | plugin API、审计存储 | 把影响预览、确认令牌、操作者、结果和补偿结果写为脱敏审计。 | 失败加载自动卸载已注册工具和 scope；不残留半挂载状态。 |
| F6-03 | MCP profile/runtime | 配置档与运行实例分离；连接串/headers 只写入安全存储。 | 预览不初始化 MCP；卸载受引用 Agent/计划会被阻止并展示依赖。 |
| F6-04 | ExtensionsPage | 显示状态版本、最后健康摘要、引用关系和可恢复动作。 | 页面打开不发现、不加载、不启动扩展。 |

### G7：桌面异步、状态一致性与国际化

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| G7-01 | `ApiWorker`、各页面 | 引入 request token、可协作取消、页面析构保护和有限超时。 | 旧请求结果不能覆盖新选择；页面关闭不调用 `terminate()` 作为常规路径。 |
| G7-02 | TaskStore/页面缓存 | 统一刷新代次、空/加载/错误状态和重试提示。 | 失败保留上次有效数据与当前选择；重复刷新可合并。 |
| G7-03 | i18n catalog/localizer | 增加键完整性检查、复数/占位符规范和对话框文案覆盖。 | 中英日切换无核心页面混合文案；缺键可诊断，不静默回退。 |
| G7-04 | 控制中心/工作台 | 将审阅详情、确认影响和错误 code 映射成一致桌面组件。 | 高风险动作均先显示影响，再二次确认；只读动作不触发网络写入。 |

### H7：验证证据、文档治理与发行门槛

| 任务 | 代码边界 | 技术目标 | 验收标准 |
|---|---|---|---|
| H7-01 | `tests/`、CI workflow | 在用户批准的验证阶段新增迁移、并发 CAS、SSE 背压、outbox、取消竞态、插件补偿与桌面 worker 测试矩阵。 | 测试报告关联到固定 commit SHA；计划阶段本身不声称已通过。 |
| H7-02 | docs/、README/报告 | 为历史“已完成/测试全绿”声明增加适用 commit、日期和历史标签。 | 当前未验证状态与历史证据可区分，避免发行误判。 |
| H7-03 | release metadata/signing workflow | 构建 manifest/SBOM、签名、安装 smoke、审批与 tag 固化成证据清单。 | 正式 `v0.1.2` 仅在 `APP_VERSION=0.1.2`、签名/验证/审批完整后允许创建。 |
| H7-04 | 运维指南 | 记录单进程限制、SQLite 规模边界、恢复/清理/导出流程和升级回退说明。 | 用户能判断本地受控自动化与未来常驻服务的差别。 |

```text
       ├─> D4 事件与背压
       ├─> E5 计划与运行生命周期
       └─> F6 扩展治理
                └─> G7 桌面一致性
                         └─> H7 验证证据与发行门槛
```

| 里程碑 | 进入条件 | 退出条件 | 阻塞项 |
|---|---|---|---|
| M-B2 | 固定 `a529ecd` 为开发基线。 | 迁移、SQLite 写入和 API error 契约已设计并实现。 | 未明确 schema 升级策略。 |
| M-C3 | B2 的状态字段与事务边界稳定。 | Run/计划取消与终态具备幂等迁移。 | 仍存在重复 Run 或状态倒退。 |
| M-D/E | C3 的 claim/CAS 可用。 | SSE/outbox 与计划恢复可观察、可限流、可关闭。 | 无界队列、无 lease 或静默异常。 |
| M-F/G | D/E 生命周期语义稳定。 | 插件和桌面层遵循相同确认、状态和错误模型。 | 全局工具残留、线程强杀或语言缺键。 |
| M-H7 | B2–G7 实现冻结，用户允许验证。 | 形成可复核证据包，之后才评估 Release Candidate。 | 未经许可运行验证或发行操作。 |

## 6. 本周期非目标与风险控制

本周期不进行分布式任务队列、云端常驻执行、团队多租户、自动模型路由、自动扩展安装、自动启动 MCP、生产遥测上报或正式 Release。SQLite 继续被定位为本地单用户存储；当需要多进程高频写入、跨主机通知或 24/7 计划时，应以独立架构决策评估常驻服务而不是继续在桌面进程内叠加线程。[5]

| 风险 | 缓解措施 | 人工确认点 |
|---|---|---|
| 迁移损坏历史本地库 | 迁移前备份提示、版本检查、只追加演进、明确回退文档。 | 引入版本化迁移框架前。 |
| 并发治理改变原有行为 | 先固化状态转移表与只读审阅，再开启新执行语义。 | 进入 C3 实现前。 |
| SSE 背压丢失用户事件 | 使用持久 cursor、明确 resync，而不是静默丢弃。 | 设置队列和保留上限前。 |
| 插件补偿影响已加载工具 | 状态机与引用图先于实际卸载；所有变更保留确认。 | 开放 F6 生命周期动作前。 |
| 发行结论被历史文档误导 | H7 统一证据索引与适用 commit 标签。 | 创建任何正式 tag 前。 |

## 7. 验证策略与当前状态

本文件定义的验收标准需要在用户明确批准验证阶段后执行。验证应优先覆盖旧库迁移、SQLite 锁竞争、Run/计划竞态、SSE 慢消费者与重放、插件补偿、桌面关闭和语言切换；随后才考虑构建、签名、跨平台安装与正式发行。

> **未验证声明：** 当前完成了静态审查、计划编写和基础实现，但没有运行测试、启动服务、执行真实模型调用、创建 Agent Run、启用计划、加载插件、构建、签名、打包、发布或创建正式 `v0.1.2` 标签。

## 8. C3–H7 基础实施记录与未验证边界

在保持“不执行测试、构建、发布或真实运行操作”的约束下，本轮已按工作包顺序写入基础实现。C3 增加 Run 的持久 `state_version`/executor lease、计划 occurrence claim、手动 `Idempotency-Key` 和终态指标 emission 去重；D4 增加 task outbox lease、退避与 SSE 批量 resync；E5 增加调度回调失败状态和 Runtime 有界关闭；F6 增加插件生命周期串行锁、加载失败回滚和有限审计尾迹；G7 增加桌面请求代次、协作取消和结构化错误显示；H7 新增验证与发行证据模板。

> 上述实现仍未经过迁移启动、API、PySide6、SSE、计划、真实 Agent Run、模型调用、插件加载、签名或发行验证。它们必须先通过 H7 证据矩阵，并获得用户对验证阶段的明确许可，才可作为正式 `v0.1.2` 候选依据。
