# CP8 发行治理冻结清单

**状态：** 静态治理冻结；当前默认状态为 **No-Go**。  
**本文件不授予：** 版本修改、提交、推送、构建、签名、资产上传、Git 标签或 GitHub Release 权限。

## 1. 发行身份的不可变前置条件

正式发行身份只能在所有下列项目均已独立完成后声明。开发标签和分支名都不能代替候选身份，且任何证据不能混用不同提交。

| 前置条件 | 所需值 | 当前状态 | No-Go 条件 |
|---|---|---|---|
| 候选提交 | 唯一、完整的 40 位 Git SHA。 | 待固定。 | 使用分支名、短 SHA、移动标签或混用 SHA。 |
| 版本身份 | 与候选 SHA 一一对应、非 `-dev` 的明确版本。 | 待确定。 | 仍为开发版本或版本/提交不一致。 |
| 远端一致性 | 本地候选、`origin/master` 与候选审阅记录可追溯。 | 待候选后核对。 | 推送失败、远端未包含候选或引用漂移。 |
| 证据包 | 按 CP6 登记册收集的最小化脱敏证据。 | `not_run`。 | 有正文、凭据、路径、原始异常或未授权证据。 |
| 批准 | 发行负责人和用户的明确、当期批准。 | 未提供。 | 缺任一批准或批准范围不包括正式发行。 |

## 3. 构建、签名与安装门槛

| 阶段 | 必需材料 | 材料绑定 | 明确禁止 |
|---|---|---|---|
| 平台构建 | Windows 与 Linux 的候选构建摘要。 | 构建输入、版本和 SHA 一致。 | 未固定候选时构建或上传资产。 |
| 完整性 | 每平台 checksum、SBOM 与构建来源摘要。 | 不披露密钥、证书私钥、用户路径或完整日志。 | 使用未审阅的第三方资产/脚本。 |
| 签名 | 受保护签名流程的验证摘要。 | 签名身份/校验结果与候选一致。 | 导出私钥、写入仓库或跳过验证。 |
| 原生安装 | 安装、启动、卸载和残留检查的脱敏结论。 | 每平台独立材料、同一候选 SHA。 | 将手工观察替代可追溯记录。 |
| 发布 | 用户和发行负责人批准后的正式 tag、资产与 Release。 | tag、Release、资产、签名与候选一一对应。 | 自动或默认创建 tag/Release。 |

## 4. 角色与职责分离

开发者可以编写代码、静态文档和候选范围说明，但不得自行批准验证或发行。验证负责人必须确认固定 SHA、授权范围、隔离环境和证据脱敏。发行负责人必须复核 CP1–CP7 证据、跨平台构建/签名/安装材料和用户批准。只有在三方职责中的适用责任均得到当期记录后，才可以由获得明确授权的操作者执行正式标签与 Release。

## 5. 发行状态机

```text
development -> candidate_frozen -> authorized_validation -> evidence_reviewed
            -> signed_and_installed -> user_approved -> release_authorized
            -> tagged_and_published
```

任何条件缺失、候选 SHA 漂移、验证 No-Go、签名/安装失败或批准撤销，都必须回到 `development` 或 `candidate_frozen`，并停止后续操作。`candidate_frozen` 并不自动授权验证；`release_authorized` 才是创建正式标签和 Release 前的必要状态，仍需要明确执行指令。

## 6. 当前 No-Go 声明

在未固定候选 SHA、未授权行为验证、CP6 证据登记册未填写、CP7 迁移/并发未验证、未完成 Windows/Linux 构建签名安装、且未获得用户发行批准时，**不得**改版本、创建或移动正式标签、签名、上传资产或创建 GitHub Release。不可变开发标签仅供追溯，不构成候选或正式版本。
