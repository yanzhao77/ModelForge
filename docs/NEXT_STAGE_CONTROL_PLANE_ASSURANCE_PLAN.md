# 下一阶段：控制面保证与验证准备计划

> **注意：** 历史基线文档，基于 v0.1.2-dev 与 v0.1.3-dev 开发阶段编写。不代表 v0.1.3-beta.1 发行状态。

**规划基线：** `7d8fdc1d2adfbb55458b2032ca4d7ebc327b60d5`（EI1–EI15 已归档并与 GitHub `master` 同步）。
**当前工作区：** 计划编写中的未提交变更；任何未来验证候选必须在单独审阅、提交后固定为唯一完整 40 位 SHA。
**版本与标签：** `APP_VERSION` 仍为 `0.1.2-dev`；`v0.1.3-dev` 继续不可变地指向 `40f06c47f4f5dbf594d7c679cfb44d6e0a7d4887`。

## 1. 目标与持续约束

本阶段不扩大运行性能力，而是将 EI1–EI15 已建立的确认、用户范围、错误码、审计摘要与桌面异步边界收敛为可追溯的控制面保证基线。重点是让每一个高风险动作拥有明确的契约来源、所有权语义、审计可表达性、桌面呈现路径和未来验证要求。

> **不变量：** 未经明确确认不得改变高风险状态；未经固定 SHA 和单独授权不得产生行为验证证据；不得通过静态代码或文档把运行时副作用、训练内部提交、任务发布器、插件/MCP 生命周期或远程 provider 调用表述为已验证、原子或可安全重放。

本轮继续禁止启动后端、桌面 GUI、SSE、迁移、Docker、pytest、Ruff、模型/provider、Agent、任务、训练、计划、插件/MCP 动作、构建、签名、标签和 Release。

## 2. 当前盘点与优先级

| 优先级 | 已知债务 | 风险 | 本阶段处理方式 |
|---|---|---|---|
| P0 | 动作风险目录、错误目录、审计白名单和 API 路由之间仍为渐进式对齐。 | 不同端点可能在未来演进中出现策略漂移。 | CP1 建立可审阅的控制面契约清单与静态覆盖检查入口。 |
| P0 | 训练服务、任务发布器与 Agent runtime 存在内部提交或独立内存状态。 | 不能承诺跨资源原子提交或安全重放。 | CP3 固化诚实的状态回执/协调边界；不改为伪原子事务。 |
| P0 | Agent Run 持久 `state_version`、lease、schedule occurrence claim 和事件唯一键仍属 C3/D4 验证债务。 | 恢复、重试和并发时可能依赖内存事实。 | CP7 完成数据库/迁移设计与证据要求，不执行迁移。 |
| P1 | 所有权与不可枚举响应已覆盖若干资源，但尚未形成统一规则。 | 后续端点可能泄露对象存在性。 | CP2 统一“可用/不可用/冲突”语义与最小响应字段。 |
| P1 | 桌面页面已采用安全错误格式化，但未形成页面覆盖清单。 | 新页面可能回退到原始异常或强制终止。 | CP5 建立页面—请求键—关闭回收—本地化映射。 |
| P1 | 验证映射尚未与控制面契约逐项交叉索引。 | 未来收集的证据难以追溯到代码策略。 | CP6 建立候选 SHA 后才能填充的证据登记册模板。 |
| P2 | 正式标签、签名、跨平台安装及发行仍无授权证据。 | 误发布风险。 | CP8 维持发行阻断与审批清单，不创建发行物。 |

## 3. 顺序工作包

| 顺序 | 工作包 | 静态交付 | 明确排除 |
|---:|---|---|---|
| CP1 | 控制面契约清单 | 以风险动作、确认码、对象类型、审计字段、错误类别和预览能力建立代码/文档映射。 | 不自动调用端点，不批量改写 API。 |
| CP2 | 所有权与不可枚举语义 | 统一资源不可用、版本冲突和管理员范围的最小响应规则。 | 不探测跨用户对象，不创建测试用户。 |
| CP3 | 审计与运行性协调边界 | 区分可同会话提交的领域状态与独立运行性副作用，定义稳定未知回执。 | 不运行训练、任务发布器、runtime、插件或 MCP。 |
| CP4 | 意图/预览生命周期 | 统一预览令牌动作、范围、过期、摘要哈希与确认的静态表述。 | 不将预览令牌变为执行令牌。 |
| CP5 | 桌面控制面覆盖矩阵 | 页面、请求键、协作取消、本地化键、确认框与安全错误显示清单。 | 不启动 GUI、SSE 或 API 请求。 |
| CP6 | 验证证据登记册 | 连接固定候选 SHA、控制面契约、脱敏证据和 No-Go 的空白登记结构。 | 不生成候选 SHA，不收集截图、网络或数据库证据。 |
| CP7 | 并发与迁移设计冻结 | Run/事件/计划/outbox 的 CAS、lease、唯一键和迁移前置条件设计。 | 不执行 DDL、迁移或恢复。 |
| CP8 | 发行治理复核 | 更新正式版本、签名、跨平台安装和审批阻断清单。 | 不改版本、不建标签、不签名、不发布。 |

## 4. 首个实施包：CP1

CP1 先新增小型、不可变的控制面契约清单。每条登记仅描述以下非敏感字段：动作码、风险目录键、确认错误码、对象类型、允许审计字段、归属语义、是否支持只读预览和错误目录类别。清单不得保存 endpoint、用户输入、目标名称、路径、URL、token、API key、模型输出、工具参数或任意 metadata。

CP1 仅为后续审阅提供单一事实来源，不导入数据库、HTTP、运行时、provider、插件或桌面 UI，不执行任何动作。完成后只允许进行文本、差异与静态依赖审阅；行为验证仍由后续固定 SHA 和明确授权控制。

## 5. 验证与发行隔离

未来行为验证需先满足：工作区提交、唯一完整 40 位候选 SHA、明确授权、隔离用户与脱敏目标。未确认动作、跨用户可见性、正文/凭据泄露、重复副作用、审计协调被表述为成功、原始异常/混合语言、未经授权运行或候选 SHA 漂移均构成 No-Go。

本计划不改变 `docs/EXECUTION_INTENT_VALIDATION_EVIDENCE_MAP.md`、`docs/EXECUTION_INTENT_GOVERNANCE_AND_VALIDATION_ISOLATION.md` 与 `docs/V0_1_3_RELEASE_GO_NO_GO.md` 的更严格门槛。
