# 本地 SQLite 增量迁移策略

ModelForge 当前使用 SQLAlchemy `Base.metadata.create_all()` 创建首次运行所需的表，并在启动时执行**仅追加**的 SQLite 列迁移。该机制适用于本地优先的单用户开发版本；它不会删除表、重命名列、回写历史 Agent 定义或修改已有 Run 数据。

## 迁移规则

| 情形 | 处理方式 | 数据安全要求 |
|---|---|---|
| 新表 | 由 `create_all()` 创建。 | 必须包含 `user_id` 或受现有用户对象所有权约束。 |
| 已有表新增列 | 通过 `PRAGMA table_info` 确认缺失后执行 `ALTER TABLE ... ADD COLUMN`。 | 新列必须允许空值或具有安全默认值。 |
| 删除/重命名/类型收窄 | 不在自动迁移中执行。 | 单独设计迁移、备份、回滚与人工确认。 |
| 索引 | 由模型的 `create_all()` 创建；复杂索引变更应作为显式版本化迁移处理。 | 不得阻塞现有数据库的启动路径。 |

应用启动在迁移前创建表，在迁移时仅检查明确列名。缺失表、只读数据库或数据库损坏不应被静默伪装为“迁移成功”：调用方必须保留明确的启动诊断。

## 开发与发行门槛

每个涉及持久化模型变更的功能切片都应记录：新表/列、默认值、旧库行为、升级后的用户隔离检查和回滚方式。进入验证阶段前，应分别在全新库和含历史 Agent/Run/Knowledge 数据的副本上执行启动与行为验证。当前开发轮不执行该验证、构建或发布。
